# 2.0.3 更新报告

状态：已发布  
适用宿主：Folia 0.8.x（针对 0.8.0 验证）

## 这一版修了什么

2.0.3 没有新界面，只修三个「让人以为模组坏了」的问题。

### 1. 升级后启用报错

**以前**：更新覆盖安装之后，手动打开开关会显示一行错误，得完全重启 Folia 才好。

```text
client activate: The requested module './lib/collections.mjs'
does not provide an export named 'expandPages'
```

**原因**：宿主给模组入口地址带版本号，但入口里引用的其它文件不带。同一个 Folia 进程里，
新入口配上了上一次留下的旧模块，两边对不上就报错。

**现在**：每个被引用的文件地址都带上自己的内容版本。内容一变地址就变，宿主会重新加载；
内容没变则继续复用。升级后不需要重启，也不会再报这一行。

**怎么确认**：更新完直接打开书库，能正常出卡片就是好的。

### 2. 更新装完没启用，也没提示

**以前**：下载并安装新版本后，模组停在「已安装、未启用」，界面上没有任何提醒。

**原因**：宿主认为「文件换了，之前的信任就不算数」，所以升级后一律先禁用；
而弹确认的入口只在用户手动打开开关时才会出现。

**现在**：安装完成后模组会主动请宿主弹一次信任确认。宿主版本没有这个入口时，
会明确提示「设置 → 模组 → bilibili 打开开关并确认信任」。

### 3. 收藏夹封面偶尔空白

**以前**：书库墙的卡片时不时没有封面，过几分钟或重启才出现；按「刷新缓存」也没用。

**现在**：

- 封面补齐交给后台队列：一次补一小批，关掉软件下次接着补
- 碰到 bilibili 限流会停下等 1 → 5 → 15 分钟，被挡下的收藏夹留在队首
- 只有确定拿到封面才更新墙面，不再出现「闪一下又没了」
- 「刷新缓存」会真的重新取一次

## 保持不变

分 P 展开、歌词页签、会员标记、四档音质、页签改名这些行为与 2.0.2 一致。

## 验证

- 自动化测试 273 通过 / 0 失败 / 3 跳过
- 真机 Folia 0.8.0：启用无报错；13 个收藏夹的封面队列能跑空；
  带版本的文件地址与不带版本的是两个独立实例（说明升级后一定会重新加载）
- 书库墙截图：四张卡都有封面，没有空白

## 已知未验

「更新后自动弹确认」需要真有新版本才能完整走一遍，本轮没有条件测试。
如果将来更新后没有弹窗，先看控制台有没有 `bili: 更新后自动启用失败`。
